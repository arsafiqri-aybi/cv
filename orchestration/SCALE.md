# CV — Scale Execution Contract v0.1

## Purpose

Scale defines the smallest execution architecture that can reliably build the CV intelligence system without lowering the scientific or operational quality floor.

Governor may optimize resources inside this envelope. Governor may not silently weaken it.

## Goal

Build a research-grounded, operational CV knowledge + reasoning system that can ultimately construct and audit CVs from real candidate evidence and real target-role requirements.

## Protected constraints

- Scope is CV only unless explicitly expanded.
- Candidate facts must never be invented.
- Scientific claims require provenance and calibrated confidence.
- Stronger contradicting evidence overrides project preference.
- Screening success and job-performance validity remain separate.
- Human screening and machine screening remain separate branches.
- ATS is not treated as one universal system.
- Module / neuron counts are not predetermined.
- Fairness is cross-cutting, not an end-stage cosmetic check.
- Accepted upstream architecture remains stable until material evidence invalidates it.

## Execution architecture

```text
S0  CONTRACT + RED-TEAM FOUNDATION
 ↓
S1  LITERATURE DISCOVERY
 ↓
S2  CLAIM / CONTRADICTION / UNCERTAINTY REGISTRY
 ↓
S3  CONSTRUCT DECOMPOSITION
 ↓
S4  SCIENTIFIC + OPERATIONAL GRAPH
 ↓
S5  CANDIDATE EVIDENCE MODEL
 ↓
S6  TARGET ROLE MODEL
 ↓
S7  REASONING ENGINE
 ↓
S8  CV CONSTRUCTION + DOCUMENT SYSTEM
 ↓
S9  HUMAN + MACHINE SCREENING AUDITS
 ↓
S10 EVALUATION + ADVERSARIAL TESTS
 ↓
S11 RUNTIME SKILL PACKAGING
 ↓
S12 RELEASE / COMPLETION AUDIT
```

Stages may iterate locally, but dependencies must not be ignored.

## Stage contracts

### S0 — Contract + red-team foundation

Required outputs:
- project contract;
- provisional architecture;
- evidence policy;
- explicit scientific non-edges;
- adversarial audit.

Pass condition:
- no major concept is retained only because it sounds intuitive.

Status:
- v0.1 established.

### S1 — Literature discovery

Objective:
Map the field broadly before deep decomposition.

Use multiple research clusters and prioritize systematic evidence.

Pass condition:
- every major architecture region has a source map;
- important modern AI/ATS/fairness developments are included;
- clear research gaps are recorded.

Do not claim saturation merely because many papers were collected.

### S2 — Evidence registries

Required:
- sources;
- atomic claims;
- contradictions;
- uncertainties;
- measurements / outcomes;
- provenance.

Pass condition:
- material architecture claims trace to evidence or are explicitly marked engineering/heuristic.

### S3 — Construct decomposition

For each construct define:
- canonical meaning;
- aliases;
- neighboring constructs;
- non-equivalences;
- evidence state;
- measurements;
- boundary conditions;
- failure modes.

Pass condition:
- duplicates and category errors are resolved before graph expansion.

### S4 — Graph architecture

Build:
- nodes;
- edges;
- non-edges;
- primary/secondary memberships;
- relationship type;
- evidence pointers.

Pass condition:
- edges are evidence-backed or explicitly provisional;
- no connection is added because concepts merely "sound related."

### S5 — Candidate evidence model

Build a schema separating reality from wording.

Pass condition:
- candidate claims can be traced to source facts;
- unsupported claims are detectable;
- uncertainty can be preserved.

### S6 — Target role model

Build role reality from:
- posting;
- work activities;
- outputs;
- KSAOs;
- seniority;
- context;
- constraints.

Pass condition:
- system does not equate job-description keyword frequency with requirement importance.

### S7 — Reasoning engine

Required reasoning chain:

```text
role requirements
→ candidate evidence
→ relevance
→ claim calibration
→ signal selection
→ prioritization
→ document decisions
```

Pass condition:
- decisions are explainable by evidence and architecture;
- unsupported polishing cannot bypass factual constraints.

### S8 — CV construction system

Build:
- section logic;
- bullet logic;
- summary logic;
- terminology;
- information hierarchy;
- document-format rules;
- context-dependent visual choices.

Pass condition:
- usable CV output without violating evidence truth.

### S9 — Screening audits

Human branch:
- attention;
- clarity;
- perceived relevance;
- credibility;
- ambiguity;
- bias risks.

Machine branch:
- parseability;
- semantic structure;
- entity extraction assumptions;
- retrieval / ranking assumptions;
- layout failure modes.

Pass condition:
- no universal ATS claim without a defined system assumption.

### S10 — Evaluation

Use separate gates for:
- factual fidelity;
- relevance;
- evidence strength;
- claim calibration;
- clarity;
- structure;
- human readability;
- parseability;
- consistency;
- fairness risk.

Pass condition:
- adversarial cases and regression tests pass at the defined scope.

### S11 — Runtime Skill

Only after domain architecture stabilizes.

Build:
- SKILL.md;
- references;
- retrieval rules;
- validators where deterministic checks are useful;
- trigger tests;
- behavioral tests.

Pass condition:
- skill performs real CV tasks without silently fabricating evidence.

### S12 — Release audit

Required:
- architecture version;
- source/version pointers;
- known limitations;
- unresolved contradictions;
- evaluation status;
- runtime status;
- completion evidence.

## Routing envelope

Use direct single-agent work where dependencies are simple.

Use bounded specialist research when:
- literature clusters are independent;
- citation screening benefits from parallelism;
- different scientific domains require focused retrieval.

Use independent verification when:
- a claim materially changes architecture;
- a source is controversial or preliminary;
- a result affects a protected constraint;
- release status is being claimed.

## Re-plan triggers

Re-enter Scale when:

- stronger evidence invalidates a protected assumption;
- the process architecture proves unable to represent a major construct;
- the graph becomes too complex to retrieve reliably;
- a required research/tool capability is unavailable;
- evaluation reveals a systematic failure mode;
- Governor reaches the envelope boundary with a required gate still failing;
- the user materially changes scope.

## Status vocabulary

- COMPLETE
- BLOCKED
- REPLAN_REQUIRED
- APPROVAL_REQUIRED
- BUDGET_EXHAUSTED
- FAIL_CLOSED

Do not use COMPLETE when required gates remain open.
