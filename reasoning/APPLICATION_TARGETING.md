# Application Targeting Reasoning v1.0

## Canonical route

```text
TARGET APPLICATION
→ SOURCE/FRESHNESS CHECK
→ REQUIREMENTS
→ TARGET ROLE MODEL
→ CANDIDATE EVIDENCE RETRIEVAL
→ MATCH / GAP MAP
→ TAILORING ACTIONS
→ CLAIM CALIBRATION
→ SECTION/DOCUMENT PRIORITY
→ TARGETED CV
→ AUDITS
```

## Target application vs target role

`Target Role` answers:
> What work/requirements define the job?

`Target Application` answers:
> Which concrete employer/vacancy/context is this CV being submitted to?

Do not merge them.

## Application-specific tailoring priority

1. hard constraints;
2. critical role requirements;
3. strong direct evidence;
4. transferable high-value evidence;
5. supported target terminology;
6. material company context;
7. cosmetic wording.

## Decision rule

A company-specific change is justified only when it changes at least one of:
- evidence selection;
- evidence priority;
- terminology;
- transferability explanation;
- hard-constraint interpretation;
- section architecture.

Otherwise reuse the vacancy/role-targeted structure.

## Evidence invariant

Across variants:

```text
FACTS = stable
CLAIM CEILING = stable unless evidence changes
SALIENCE = may change
ORDER = may change
DETAIL = may change
TERMINOLOGY = may change if semantically equivalent
```

## Variant comparison

Compare variants by:
- requirement coverage;
- factual integrity;
- relevance;
- evidence strength;
- clarity;
- document quality.

Do not score "personalization intensity" as a goal in itself.
