# Tailoring Rules v1.0

## Definition

Tailoring is:

> Target-specific evidence selection, prioritization, terminology alignment, and contextual framing performed without changing the underlying candidate facts or exceeding claim calibration.

## Allowed transformations

### SELECT
Choose evidence that best supports important target requirements.

### OMIT
Remove low-value evidence when document space or relevance requires it.

Omission must not create a materially false chronology or identity.

### REORDER
Increase salience of high-priority evidence.

### EMPHASIZE
Allocate more document space/detail to strong relevant evidence.

### TERMINOLOGY ALIGN
Use target-recognizable terminology when:
- it is semantically accurate;
- the candidate evidence supports it.

### CONTEXTUALIZE
Explain transferability between candidate context and target context.

### SECTION PRIORITY
Move Projects, Education, Skills, Certifications, or other sections when the target application makes them more diagnostic.

## Forbidden transformations

- inventing a required skill;
- copying a tool into Skills because it appears in the JD;
- changing a job title into the target title without factual basis;
- fabricating company-specific motivation;
- claiming familiarity with the company's products without evidence;
- adding unsupported metrics;
- hiding a material hard-constraint gap;
- keyword stuffing;
- mimicking stated company values as personality claims.

## Company context rule

Company context is **secondary** to role/vacancy relevance.

Use it only when it changes a legitimate CV decision.

Good:
- foregrounding fintech compliance experience for a fintech role;
- foregrounding B2B SaaS work when the target product is B2B SaaS;
- using the employer's accurate term for a capability the candidate genuinely has.

Weak:
- inserting the employer's mission statement;
- claiming "passionate about innovation" because the careers page says innovation;
- rewriting identity to match culture language.

## Variant reuse

Reuse a prior variant when:
- target requirements are materially similar;
- company context does not change evidence priority;
- source freshness remains acceptable.

Create a new variant when:
- role changes;
- important requirements change;
- hard constraints change;
- evidence priority materially changes;
- company/domain context materially changes interpretation.

Do not create unique variants merely to increase file count.
