# Application Targeting Output Contract v1.0

For a serious targeted CV task, produce internally or explicitly as appropriate:

## 1. Target Application
- company
- vacancy
- target role
- targeting level T0–T3
- source/freshness
- hard constraints

## 2. Requirement Map
Classify:
- critical
- high
- medium
- low/unknown

Distinguish:
- hard constraint
- strong preference
- preference

## 3. Candidate Evidence Map
For each material requirement:
- direct evidence
- adjacent evidence
- transferable evidence
- no evidence

## 4. Gap Report
Classify:
- hard-constraint gap
- evidence gap
- terminology gap
- transferability gap
- provenance gap
- recency gap

## 5. Tailoring Decisions
Record:
- SELECT
- OMIT
- REORDER
- EMPHASIZE
- TERMINOLOGY_ALIGN
- CONTEXTUALIZE
- SECTION_PRIORITY

Each material decision must point to a role/company-context reason.

## 6. CV Variant
The finished CV variant must preserve:
- factual evidence;
- chronology;
- attribution;
- claim strength;
- canonical date/consistency standards.

## 7. Variant Metadata
Record:
- application_id
- candidate evidence version/snapshot
- target role version
- generated date
- unresolved gaps

## Completion

A targeted variant is complete when:
- the target application is explicit;
- strong relevant evidence is surfaced;
- unsupported matches are absent;
- company context is used only when material;
- no critical gaps are disguised;
- root CV and document-structure audits pass.
